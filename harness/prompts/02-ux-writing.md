# 3. UX 라이팅 규칙 (오늘의집 LP)

기준: `docs/Section-Guidelines.md §6` + 오늘의집 서비스 톤. `lp validate` 가 기계적으로 검사하는 항목은 ✅ 표시.

## 톤
- **해요체, 짧은 문장.** 한 문장 = 한 메시지. 같은 섹션 안에서 합니다체·평서체와 섞지 않는다 ✅
- 고객 입장에서 얻는 결과를 먼저: "견적 비교 서비스 제공" → "견적을 한 번에 비교해요"
- 시스템 용어 대신 고객이 아는 말: "파트너사 매칭" → "업체 연결"
- 과장·단정 금지: 최고, 최저가, 업계 1위, 무조건, 100%, 완벽, 평생, 절대 ✅ (근거 각주가 있을 때만 예외)
- 숫자·보장·조건은 원문 그대로. 반올림·추정 금지.

## 줄바꿈 판단
- 히어로·섹션 타이틀은 `\n` 을 쓰지 말고 한 줄로 쓴다. 하네스가 글꼴 실측 폭으로 모바일에서 넘치는지 재고, 넘치거나 12자 이상이면 **의미 단위(쉼표·조사 뒤)에서 균형 잡힌 2줄**로 끊는다. 리포트 `info` 에 적용 결과가 남는다.
- 어색하게 끊겼으면 그 자리만 `\n` 으로 직접 지정한다.
- 수식어 뒤("검증된 | 전문가", "다른 | 모습")나 1글자 고아("집\n") 는 하네스가 피하지만, 애초에 수식어가 긴 문장은 두 문장으로 나누는 편이 낫다.

## 길이 감각
- 렌더 QA 가 실제 375/768/1280 폭에서 말줄임을 잡는다. `실제 폭에서 잘림` 경고가 나오면 핵심어를 앞으로 당겨 줄인다.
- leading-asset 카드 본문은 카드 폭 260–300px → 줄당 약 15자. 2줄 넘으면 잘린다.
- 표 행 텍스트는 ≈8자 이하로 쓰면 모바일에서 표 2개가 나란히(2열) 붙는다. 넘으면 세로 스택.
- 모바일 캐러셀 카드 타이틀은 1줄 약 11–12자.

## 워싱 요청이 따로 오면
`design:ux-copy` 스킬 기준으로, 추천안 1개 + 톤이 다른 대안 3개(A/B/C) 표 + 근거로 응답한다.
